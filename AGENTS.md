# gcard-usage — GPU Monitor Web UI

A lightweight C program that monitors GPU utilization and VRAM usage, serving a real-time web dashboard via an embedded HTTP server.

## Architecture

- **Language**: C (compiled with gcc)
- **HTTP framework**: [Mongoose](https://github.com/cesanta/mongoose) — single-file embeddable web server (`mongoose.c` / `mongoose.h`)
- **Frontend**: Embedded HTML/JS served from a C string (`index_html.h`, generated by `embed_html.sh`)
- **Charts**: Chart.js loaded from CDN

## GPU Backends (pick one at compile time)

| Target | Flag       | Library          | API used           |
|--------|------------|------------------|--------------------|
| NVIDIA | `-DUSE_NVML` | `-lnvidia-ml`   | NVML (`nvmlDeviceGetUtilizationRates`, `nvmlDeviceGetMemoryInfo`) |
| AMD    | `-DUSE_ROCM` | `-lrocm_smi64`  | ROCm SMI (`rsmi_dev_busy_percent_get`, `rsmi_dev_memory_usage_get`) |

Exactly one of `USE_NVML` or `USE_ROCM` must be defined; otherwise compilation fails.

## Build

```bash
make cuda   # NVIDIA
make rocm   # AMD
make clean  # remove binary and generated header
```

The `embed` target runs `embed_html.sh` to embed `index.html` into `index_html.h` before compiling. Both `cuda` and `rocm` targets depend on `embed`, so the HTML is always up-to-date.

Optional flags:
- `DEBUG=1` — enables debug prints (HTTP request logging, GPU read timestamps)

## Runtime Behavior

1. Initializes the selected GPU framework (NVML or ROCm SMI)
2. Detects GPU count and caps at `MAX_GPUS` (16)
3. Starts Mongoose HTTP server on `http://0.0.0.0:8000`
4. **Waits 10 seconds** before the first GPU read (lets other processes settle)
5. Enters main loop:
   - Queries GPU stats **once per second** and caches them in `cached_stats[]` — prevents driver deadlocks
   - Serves HTTP requests from the cache (no blocking GPU calls on the request path)
   - `mg_mgr_poll(&mgr, 200)` yields for 200ms between iterations

## HTTP API

| Route       | Response                          |
|-------------|-----------------------------------|
| `/`         | Embedded HTML dashboard           |
| `/index.html` | Same as `/`                    |
| `/stats`    | JSON array: `[{"id": 0, "gpu_percent": 42, "vram_percent": 67}, ...]` |
| *(anything else)* | 404 Not Found              |

## Frontend

The dashboard (`index.html`) polls `/stats` every 1 second and dynamically builds per-GPU cards with:
- Compute utilization (progress bar + percentage)
- VRAM usage (progress bar + percentage)
- Line chart (60-second history, Chart.js)

## Key Design Decisions

- **No BASE_PATH** — routes are fixed at `/`, `/index.html`, and `/stats`. No reverse-proxy prefix support.
- **Caching** — GPU queries happen on a fixed 1-second cadence in the main loop; HTTP handlers read from `cached_stats[]` only. This prevents driver deadlocks when GPUs are busy with inference workloads (e.g., llama.cpp).
- **10-second startup delay** — gives other GPU consumers time to initialize before the first read.
- **Embedded HTML** — `index.html` is converted to a C string array at build time, so the binary is fully self-contained.

## Files

```
main.c          — GPU backend + HTTP server (entry point)
mongoose.c/.h   — Mongoose HTTP library (vendored)
index.html      — Dashboard frontend (source, embedded at build)
index_html.h    — Generated C header from index.html (auto-generated, not committed)
embed_html.sh   — Script to embed index.html into index_html.h
Makefile        — Build targets (cuda / rocm)

```
